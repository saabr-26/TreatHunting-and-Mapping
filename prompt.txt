# PROJECT: Threat Hunting & Security Investigation Platform

You are an expert cybersecurity engineer, SOC analyst, SIEM engineer, backend developer, frontend developer, and security-project mentor.

I want you to help me build a complete portfolio-grade cybersecurity project called:

# "Threat Hunting & Security Investigation Platform"

The project must demonstrate practical SOC Analyst skills using real security datasets, Splunk, SPL, MITRE ATT&CK, threat hunting, log analysis, investigation, correlation, timelines, and incident reporting.

Do NOT make this a generic cybersecurity dashboard.

The core purpose is:

> Take real security logs → ingest them into Splunk → perform threat hunting using SPL → identify suspicious behavior → investigate related events → reconstruct an attack timeline → map observed behavior to MITRE ATT&CK → create investigation cases → visualize findings in a web UI → generate a professional SOC investigation report.

---
# 1. MY ENVIRONMENT

I am developing this project on a Windows 11 machine.

I already have Splunk installed on Windows and Splunk Web is working correctly.

Splunk Web:

http://localhost:8000

Important distinction:

* Port 8000 = Splunk Web interface
* Port 8089 = Splunk management/REST API by default

The existing Splunk installation should be used as the SIEM and event-search engine.

I do NOT want to replace Splunk with a custom fake SIEM or a normal database.

The initial development environment should run directly on Windows because this makes communication with the existing local Splunk installation easier.

Recommended initial local architecture:

Windows 11
│
├── Splunk
│     ├── Splunk Web: localhost:8000
│     └── Splunk REST API: localhost:8089
│
├── Django Backend
│     └── localhost:8001
│
└── React Frontend
└── localhost:3000

Communication:

Browser
↓
React Frontend
↓
Django REST API
↓
Splunk REST API
↓
Splunk Index
↓
Security Events

The Django backend must communicate with Splunk rather than allowing the React frontend to directly access Splunk credentials or the Splunk API.

Splunk credentials must never be placed in frontend code.

Use environment variables in the Django backend:

SPLUNK_HOST=localhost
SPLUNK_PORT=8089
SPLUNK_USERNAME=<configured Splunk username>
SPLUNK_PASSWORD=<configured Splunk password>
SPLUNK_INDEX=threathunt
SPLUNK_VERIFY_SSL=false

Do not commit the actual credentials to GitHub.

Use a `.env.example` file containing placeholder values.

For the first implementation, do NOT require Docker for Splunk.

If Docker is later used for Django, React, or PostgreSQL, remember that `localhost` inside a Docker container refers to the container itself. The container should communicate with the Windows host using an appropriate host address such as `host.docker.internal` where supported.

First make the complete application work directly on Windows.

Only introduce Docker after the basic application and Splunk integration are working correctly.

# 5. MITRE ATT&CK INTEGRATION

Integrate MITRE ATT&CK into the project.

For every detection/hunt, store:

* Technique ID
* Technique name
* Tactic
* Description
* Evidence
* Related SPL query
* Investigation case
* Confidence

Examples:

T1059.001 — PowerShell

T1059.003 — Windows Command Shell

T1078 — Valid Accounts

T1136.001 — Create Account: Local Account

T1560 — Archive Collected Data

Do NOT automatically map every event to MITRE.

MITRE mapping must be evidence-based.

For example:

Event:
PowerShell process creation

CommandLine:
powershell.exe -enc ...

Then:

T1059.001 — PowerShell

is a reasonable mapping.

But do not claim a complete attack technique solely because one generic event exists.
